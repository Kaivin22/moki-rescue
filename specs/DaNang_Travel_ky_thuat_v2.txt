Mục đích:
  Ứng dụng lập lịch trình du lịch thông minh cho Đà Nẵng và Hội An.
  Tự động tối ưu lộ trình (Route Optimization Algorithm) theo ngày, sở thích,
  budget, phương tiện và giờ mở cửa thực tế. Chia sẻ lịch trình qua QR/link.
  AI chatbot hỏi đáp dựa trên dữ liệu thật (RAG pattern).

Phạm vi v1.0: TP. Đà Nẵng + Hội An + vùng lân cận (bán kính 100km).

Đối tượng:
  • anonymous  — xem địa điểm, đọc thông tin, xem lịch trình public
  • user       — tạo/lưu lịch trình, AI chat, review, chia sẻ QR
  • editor     — nhập liệu bổ sung địa điểm (nội bộ)
  • admin      — vận hành hệ thống, sync Google, xử lý ticket

-- Trigger: sync location từ lat/lng
CREATE OR REPLACE FUNCTION sync_place_location() RETURNS TRIGGER AS $$
BEGIN
  NEW.location := ST_SetSRID(ST_MakePoint(NEW.lng, NEW.lat), 4326)::geography;
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;
CREATE TRIGGER trg_sync_place_location
  BEFORE INSERT OR UPDATE OF lat, lng ON public.places
  FOR EACH ROW EXECUTE FUNCTION sync_place_location();

-- Trigger: cập nhật rating_avg trên places
CREATE OR REPLACE FUNCTION update_place_rating() RETURNS TRIGGER AS $$
BEGIN
  UPDATE public.places SET
    rating_avg   = ROUND((SELECT AVG(rating) FROM public.reviews
                          WHERE place_id = COALESCE(NEW.place_id, OLD.place_id))::NUMERIC, 2),
    rating_count = (SELECT COUNT(*) FROM public.reviews
                    WHERE place_id = COALESCE(NEW.place_id, OLD.place_id))
  WHERE id = COALESCE(NEW.place_id, OLD.place_id);
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;
CREATE TRIGGER trg_update_place_rating
  AFTER INSERT OR UPDATE OR DELETE ON public.reviews
  FOR EACH ROW EXECUTE FUNCTION update_place_rating();

-- profiles: tự đọc/ghi
ALTER TABLE public.profiles ENABLE ROW LEVEL SECURITY;
CREATE POLICY "read_own"   ON public.profiles FOR SELECT USING (auth.uid() = id);
CREATE POLICY "update_own" ON public.profiles FOR UPDATE USING (auth.uid() = id);
CREATE POLICY "insert_own" ON public.profiles FOR INSERT WITH CHECK (auth.uid() = id);

-- places: mọi người đọc, editor/admin ghi
ALTER TABLE public.places ENABLE ROW LEVEL SECURITY;
CREATE POLICY "read_active_places" ON public.places FOR SELECT
  TO anon, authenticated USING (is_active = TRUE);
CREATE POLICY "editor_admin_write" ON public.places FOR ALL TO authenticated
  USING (EXISTS (SELECT 1 FROM public.profiles
                 WHERE id = auth.uid() AND role IN ('editor','admin')));

-- distances: mọi người đọc, admin ghi
ALTER TABLE public.distances ENABLE ROW LEVEL SECURITY;
CREATE POLICY "read_distances" ON public.distances FOR SELECT
  TO anon, authenticated USING (TRUE);
CREATE POLICY "admin_write_distances" ON public.distances FOR ALL TO authenticated
  USING (EXISTS (SELECT 1 FROM public.profiles WHERE id = auth.uid() AND role = 'admin'));

-- itineraries: owner quản lý, public/published mọi người đọc
ALTER TABLE public.itineraries ENABLE ROW LEVEL SECURITY;
CREATE POLICY "owner_manage"    ON public.itineraries FOR ALL USING (auth.uid() = user_id);
CREATE POLICY "read_published"  ON public.itineraries FOR SELECT
  TO anon, authenticated USING (is_public = TRUE OR status = 'published');

-- itinerary_days
ALTER TABLE public.itinerary_days ENABLE ROW LEVEL SECURITY;
CREATE POLICY "owner_days" ON public.itinerary_days FOR ALL USING (
  EXISTS (SELECT 1 FROM public.itineraries WHERE id = itinerary_id AND user_id = auth.uid())
);

-- itinerary_places
ALTER TABLE public.itinerary_places ENABLE ROW LEVEL SECURITY;
CREATE POLICY "owner_places" ON public.itinerary_places FOR ALL USING (
  EXISTS (SELECT 1 FROM public.itinerary_days d
          JOIN public.itineraries i ON i.id = d.itinerary_id
          WHERE d.id = day_id AND i.user_id = auth.uid())
);

-- reviews: mọi người đọc, user ghi review của mình
ALTER TABLE public.reviews ENABLE ROW LEVEL SECURITY;
CREATE POLICY "read_reviews" ON public.reviews FOR SELECT TO anon, authenticated USING (TRUE);
CREATE POLICY "own_reviews"  ON public.reviews FOR ALL TO authenticated
  USING (auth.uid() = user_id);

-- support_tickets: user đọc/tạo của mình, admin full
ALTER TABLE public.support_tickets ENABLE ROW LEVEL SECURITY;
CREATE POLICY "read_own_ticket"   ON public.support_tickets FOR SELECT USING (auth.uid() = user_id);
CREATE POLICY "create_ticket"     ON public.support_tickets FOR INSERT TO authenticated
  WITH CHECK (auth.uid() = user_id);
CREATE POLICY "admin_full_ticket" ON public.support_tickets FOR ALL TO authenticated
  USING (EXISTS (SELECT 1 FROM public.profiles WHERE id = auth.uid() AND role = 'admin'));

-- group_votes: mọi người tạo, owner đọc
ALTER TABLE public.group_votes ENABLE ROW LEVEL SECURITY;
CREATE POLICY "anyone_vote" ON public.group_votes FOR INSERT TO anon, authenticated
  WITH CHECK (TRUE);
CREATE POLICY "owner_read_votes" ON public.group_votes FOR SELECT USING (
  EXISTS (SELECT 1 FROM public.itineraries
          WHERE id = itinerary_id AND user_id = auth.uid())
);

ROUTE OPTIMIZATION ALGORITHM
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

File: lib/features/itinerary/domain/services/route_optimizer.dart
Test: test/features/itinerary/route_optimizer_test.dart (TDD — viết test trước)

Input:
  List<Place>       places          — địa điểm đã chọn
  int               numDays         — số ngày
  Transport         transport        — phương tiện
  TimeOfDay         startTime        — giờ bắt đầu mỗi ngày (mặc định 08:00)
  TimeOfDay         endTime          — giờ kết thúc mỗi ngày (mặc định 20:00)
  int?              budgetTotal      — ngân sách tổng (VND, nullable)

Output: ItineraryResult (List<ItineraryDay> với PlaceWithTime mỗi ngày)

BƯỚC 1 — K-means Geographic Clustering:
  Phân nhóm places thành numDays cluster theo tọa độ GPS.
  Mục tiêu: địa điểm gần nhau về địa lý vào cùng 1 ngày.
  Thuật toán K-means đơn giản implement bằng Dart (không cần package ML).
  Iteration tối đa: 100 lần hoặc đến khi centroid không đổi.

BƯỚC 2 — Greedy Nearest Neighbor trong mỗi cluster:
  Bắt đầu từ địa điểm mở cửa sớm nhất.
  Chọn lần lượt địa điểm chưa thăm có distance nhỏ nhất.
  Đọc duration từ bảng distances trong Supabase DB (KHÔNG gọi API).
  Nếu không có trong distances: tính Haversine làm fallback tạm thời.

BƯỚC 3 — Constraint Checking (giờ mở cửa):
  Tính giờ đến: prevArrival + prevDuration + travelTime.
  Nếu arrival < openingTime: thêm waiting time.
  Nếu arrival > closingTime: đổi vị trí địa điểm hoặc chuyển sang ngày sau.
  Nếu vượt endTime: cắt địa điểm cuối, trả về warning.

BƯỚC 4 — Budget Check:
  Tổng entry_fee của tất cả địa điểm <= budgetTotal.
  Nếu vượt: trả về BudgetWarning (không throw error, user tự quyết).

BƯỚC 5 — Output assembly:
  Gắn arrival_time, duration_min, estimated_cost cho mỗi PlaceWithTime.
  Tính estimated_cost tổng mỗi ngày và toàn lịch trình.

WEIGHTED SCORING RECOMMENDATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

File: lib/features/itinerary/domain/services/place_recommender.dart

score = styleMatch×40 + ratingScore×25 + budgetScore×20 + popularityScore×15

styleMatch     = (tags trùng travel_style) / len(travel_style) [0.0–1.0]
ratingScore    = rating_avg / 5.0
budgetScore    = 1.0 nếu entry_fee_max <= budget_per_person
                 0.5 nếu 100% < chi phí <= 150%
                 0.0 nếu > 150%
popularityScore= min(rating_count / 100, 1.0)

Filter trước khi score:
  - Bỏ các place đã có trong visited_place_ids
  - Bỏ place đóng cửa tháng hiện tại (best_months không chứa tháng hiện tại)
  - Bỏ place không phù hợp suitable_for (nếu user đã chọn travel_with)

File: lib/features/ai_chat/data/datasources/gemini_datasource.dart

RAG Flow:
  1. Parse intent từ câu hỏi user (tên địa điểm hay câu hỏi chung?).
  2. Query Supabase lấy dữ liệu địa điểm liên quan (top 5 theo relevance).
  3. Inject JSON data thật vào system prompt:
     "Dữ liệu địa điểm: [JSON]. Chỉ dùng thông tin này, không suy đoán."
  4. Gemini diễn giải → trả về text.
  5. Parse {{PLACE:tên}} tokens trong response → tạo PlaceCard deep-link.

System Prompt (bắt buộc đủ 4 phần):
  VAI TRÒ: Hướng dẫn viên du lịch địa phương tại Đà Nẵng.
  ĐƯỢC PHÉP: Tư vấn địa điểm, ẩm thực, di chuyển, thời tiết, văn hóa.
  KHÔNG ĐƯỢC: Sức khỏe y tế, pháp lý, tài chính đầu tư, ngoài phạm vi du lịch.
  FORMAT: Khi nhắc địa điểm dùng {{PLACE:tên}} để app parse deep-link.

Rate Limiting — kiểm tra SERVER-SIDE (không tin client):
  Free: 15 tin nhắn/ngày. VIP: không giới hạn.
  Trước khi gọi Gemini: đọc profiles.ai_msg_count + ai_msg_reset_date.
  Nếu reset_date < today: reset count = 0.
  Nếu count >= limit: từ chối, không gọi API.
  Sau response thành công: tăng count += 1.

Xử lý lỗi:
  HTTP 429: "AI đang bận, thử lại sau ít phút."
  Timeout >15s: hủy request, hiện nút "Thử lại".
  Safety filter: "Câu hỏi này nằm ngoài phạm vi tư vấn du lịch."
  Không bao giờ mất lịch sử chat dù gặp lỗi.
